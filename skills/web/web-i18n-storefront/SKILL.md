# 前端站点多语言改造

适用：已经有一套 `l(en, zh)` 式双语函数的前端站点，要扩到 5–8 种语言，且不能改上千处调用点。
不适用：从零设计 i18n 框架（另按框架文档办）、需要服务端渲染按语言出 HTML 的项目。

## 一、先把签名保住，再换实现

原站点里几乎每个文案都是 `l('English', '中文')`。**不要重写调用点**，只把 `l` 的内部换成「以英文原文为键」的查表：

```js
const l = (en, zh) => LC_I18N.t(lang, en, zh);
// t: zh → 原有中文（一字不改）；en → 英文原文；其它 → 字典[lang][en]，缺键回退英文
```

好处：上千处调用零改动；缺键只会显示英文，不会出现空串或 `[object Object]`；以后加语言只是多一本字典。

同时收敛三件事到一个注册表（`i18n/base.js`）：语言顺序、顶栏短标签、BCP47、金额/日期用的 locale、
`<html lang/dir>` 同步。语言名要**按当前界面语言显示**（中文界面看到「法语」，法语界面看到「Chinois」），
这张对照表（8×8）手写，别指望机翻。

## 二、词典用「抽取 → 机翻 → 校正」三段流水线，不要手抄

```
tools/i18n/
├─ extract.py     从源码抽 l('en','zh')、en:/zh: 对象对、双语数组，落 strings.json
├─ translate.py   批量机翻 + 套术语表/人工覆盖，输出 i18n/<code>.js
├─ cache.json     机翻缓存（重跑不再请求网络）
├─ glossary.json  术语级正则修正
├─ overrides.json 人工校对的高频文案（优先级最高）
└─ extras.json    没有中文对照的英文串，直接给各语言定稿
```

要点：
- 键就是英文原文，所以 `extract.py` 的抽取正则要能吃**跨行**调用（`l(\n  'x',\n  'y')`）。
- 目录型数据（产品名、系列名、案例注释）经常写成 `['English','中文']` 双语数组，也要抽，
  但消费端必须先改成 `pick(pair)` 才能翻译，见下面 P5。
- 机翻只是基线。短词最容易错：报价被译成「约会/请柬」、招牌被译成「信号/星座符号」、
  面光被译成「人脸发亮」、上限被译成「瓶塞」。这类必须进 `overrides.json`。

## 三、七个真实的坑

### P1 切了语言，某些区块纹丝不动

**现象**：导航和主视觉都变了，但某个独立模块（案例墙、AI 结果页）整块还是旧语言。
**根因**：模块在**脚本加载时**把 `localStorage` 里的语言读进闭包变量，页面内切换只重渲染容器，
闭包里的值不会更新。
**修法**：模块里加 `cur()`，`l()`、双语数组取值全部走 `cur()`（每次现取），不要读快照。
**推论**：**生成型内容**（AI 方案卡、诊断书、报价摘要这类「当时拼好的字符串」）光重渲染没用，
要记录 `builtLang`，语言变了就按当前语言重建数据，并保留用户已选的项。

### P2 机翻跑完，一批词条译文等于原文

**现象**：某个语言的词典里几十上百条 `值 === 键`，页面显示英文。
**根因**：批量端点一次塞二十条以上长句时会悄悄少返回几条；条数对不上整批作废，
代码把「没拿到译文」写成了原文。
**修法**：`_call()` 检测条数，不符就**二分重试**，最后退回逐条请求；缓存里「值等于键」的条目清掉重取。
**验收口径**：按语言统计 `译文 === 原文` 且含拉丁字母的条目；西里尔／阿拉伯语系必须为 0
（这两种文字不可能与英文同形），拉丁语系允许少量同形词（Material、Design、Original）。

### P3 带变量的句子永远翻译不了

**现象**：`l('save ~' + n + '% vs my pick', ...)` 这类句子在非中文界面回落英文。
**根因**：键里含数字和店名，查表永远查不到。
**修法**：单独一张 `PHRASES` 模板表，每种语言一条带 `{n}`/`{name}`/`{q}` 占位符的句子，
用 `phrase(key, vals)` 填充。别试图用正则把变量从键里剥出来——语言语序不同，剥了也拼不回去。

### P4 只有英文一种写法的字段

**现象**：材质、风格这类来自 AI 出图提示或第三方接口的英文短语，抽取脚本抓不到（没有中文对照）。
**修法**：`extras.json` 直接给六种语言的定稿，`translate.py` 合并进词典；
消费端用 `tr1(text)`（命中词典就翻译，缺键原样返回），不要塞进双语数组。

### P5 双语数组的下标写法是定时炸弹

**现象**：`name[lang === 'zh' ? 1 : 0]` 到处出现，加第三种语言时全部只返回英文。
**修法**：统一换成 `pair(['English','中文'])` → 走词典；万一某处必须保留下标，
也要把 `zi` 收敛成 `cur() === 'zh' ? 1 : 0`，并明确「非中英一律取 0（英文）」是已知边界。

### P6 切换语言后首屏高度、区块位置全在跳

**现象**：同一条文案中文两行、法语五行，首屏高度从 600 变到 880，下面的区块跟着上下窜。
**根因**：主视觉是 `height:auto; min-height:XXX`，高度被文案撑开。
**修法**（两步，缺一不可）：
1. **定高**：主视觉改固定高度（按断点给 3–4 档），文案块在定高内垂直居中。
2. **fit to box**：渲染后比较文案高度与可用高度，超了就把一个缩放系数（CSS 变量）
   每档降 0.02，最低 0.78，等比缩标题与正文——**只缩不裁**，缩排无感知。窗口变化要重算。
3. 顺带把**同区块内的卡片、区块标题**也钉最小高度：卡片正文多一行、标题说明多一行，
   都会把下面的内容顶偏 11–25px，等比缩排救不了这个。

**验收口径**：多语言 × 多断点跑一遍，比对「首屏高 / 卡片顶 / 卡片高 / 下一段落起点」四项，
必须逐项相等（±2px 内算过，来自标题换行）。

### P7 删旧代码时，连带删掉旁边的工具函数

**现象**：把一块独立区块并进另一个区块，用区间替换删函数时，把紧邻的另一个函数一起删了，
页面报 `xxx is not defined`，但那块 UI 看起来没坏（错误发生在渲染后）。
**修法**：区间替换前后各 `grep -c "function <名>"` 点名确认；改完立刻跑一次页面级
`pageerror` 监听（不是看截图），错误只在控制台。

## 四、RTL 与字体：先问「值不值得镜像」

- 整站 `dir="rtl"` 会让所有绝对定位的版式错位（实测主视觉的文案块直接跑出画面）。
  版式不是按 RTL 设计的站点，**只切文案与字形、布局保持 LTR** 更稳；真要 RTL 就逐页校准，别一把梭。
- 拉丁字体通常没有阿拉伯字形，要给 `html[lang="ar"]` 单独的字族回退；阿拉伯语不要加 `letter-spacing`。
- 金额用 `Intl.NumberFormat(locale, {currency})`，阿拉伯语固定拉丁数字
  （locale 后缀 `-u-nu-latn`），否则金额会变成阿拉伯数字，财务看不懂。

## 五、上线前的四道验收

1. **CJK 残留扫描**：非中文语言遍历主要视图，扫正文叶子节点 + `placeholder` + `alt`，必须为 0；
   只允许用户自己输入的文本（例如询价备注）含中文。
2. **同形词审计**：见 P2 的口径。
3. **坐标比对**：见 P6 的口径。
4. **端到端切换**：点下拉 → 断言 `html lang`、触发器短标签、导航首项文本、`localStorage` 值；
   再切回中文，确认还原。

## 六、缓存：改内容不如改文件名

静态站没有 `Cache-Control` 时，浏览器会启发式缓存，`?v=时间戳` 也可能命中旧文件。
每次动 JS/CSS 就把 `index.html` 里所有引用的版本号统一换一个（如 `?v=20261027-fit6`），
比解释「你强刷一下」可靠。

## 七、交付物形态

```
i18n/base.js            语言注册表 + t/pick/label/name/locale/apply
i18n/<code>.js          每语言一本字典（生成物，不手改）
i18n.css                语言下拉宽度、阿拉伯语字族、RTL 补丁、小屏面板
tools/i18n/*.py         抽取/翻译/术语/覆盖/缓存
```

一句话总结：**键用英文原文、语言现取现用、生成型内容跟着重算、版面靠定高加等比缩排。**
