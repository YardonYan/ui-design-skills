# 消息状态清单

按一条用户消息从发出到结束列。每一条都要有对应的界面表现，缺一条就是链路没做完。

## 发送前

| 状态 | 界面要求 |
|---|---|
| 空态 | 给出能直接点的起步建议，不要只放一个输入框 |
| 有草稿 | 保留草稿，失焦与切会话不丢 |
| 上一次还在进行 | 明确显示「上一条还在跑」，并说清新输入是排队还是打断 |
| 不可发送 | 说明原因，例如附件超限、后端未连接，不只把按钮置灰 |

## 进行中

| 状态 | 界面要求 |
|---|---|
| 等待首个 token | 有明确的等待反馈，且能取消 |
| 流式输出 | 按分片追加，滚动跟随只在用户处于底部时生效 |
| 工具调用中 | 显示正在做什么，不显示原始参数 JSON 就完事 |
| 多步推理 | 可折叠，默认收起但可展开查看 |
| 用户手动停止 | 保留已生成内容，标注「已停止」，提供继续或重发 |

## 结束与异常

| 状态 | 界面要求 |
|---|---|
| 正常完成 | 给出复制、重试、赞踩等后续动作，但不堆叠 |
| 内容被截断 | 明确标注不是完整回答，说明原因 |
| 失败 | 说清失败在哪一段，给出重试与改述两条出路 |
| 断线重连 | 显示重连状态与是否可恢复，不把历史消息清空 |
| 部分成功 | 已完成的工具结果与未完成的回答要分开表达 |
| 内容被审核拦截 | 给出可理解的说明，不留空白气泡 |

## 展示细节

- Markdown、代码、表格、公式要在流式过程中逐步可渲染，不能等全部结束才出现格式。
- 代码块要有语言标注与复制按钮；长内容默认折叠但不隐藏。
- 引用与来源单独成区，不混进正文气泡。
- 时间戳、模型名、耗时这类元信息放在次级位置，不抢正文。
