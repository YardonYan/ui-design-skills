# 工具调用与人工审批

工具调用是 AI 界面与普通聊天的分界线。用户要判断「让不让它做」，界面就必须把决定所需的信息摆全。

## 展示的三个层次

1. 摘要层：一句话说清要做什么，例如「将查询订单 1234 的状态」。
2. 参数层：可展开查看具体参数，用人类可读的标签而不是原始字段名。
3. 结果层：成功给结果摘要，失败给原因与可重试入口；耗时长的给进度。

## 审批卡必须包含

| 项 | 要求 |
|---|---|
| 动作描述 | 用动词开头，说清作用对象 |
| 影响范围 | 会改动什么、是否可逆、是否涉及外部系统 |
| 参数 | 默认可展开，敏感值脱敏显示 |
| 两个明确动作 | 批准与拒绝并列，不要只给一个「继续」 |
| 超时行为 | 说清不操作会怎样，别静默执行 |
| 结果回写 | 批准后状态变成「已执行」，拒绝后变成「已拒绝」，都能追溯 |

## 常见偏差

- 只把模型输出的工具参数 JSON 原样贴出来：用户无法据此判断风险。
- 审批通过后卡片消失：会话历史里失去「谁批准了什么」这条证据。
- 工具失败只显示红色感叹号：不给重试，也不给改用别的方式。
- 多个工具并发时整齐排列但不标顺序：用户分不清依赖关系。
- 生成式界面里让模型直接输出任意 HTML：应当从产品自己提供的组件词表里组合。

## 生成式界面

模型组合界面时，组件词表由产品定义，模型只选组件与填数据。界面要处理三种情况：组件名不存在、参数不合法、渲染抛错，都要降级成可读的文本卡片，而不是白屏。
