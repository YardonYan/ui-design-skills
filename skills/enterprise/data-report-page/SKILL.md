# 数据汇报页

## 什么时候用

- 一期销售、经营、运营、检索或案件数据，要整理成一份给老板/客户讲明白的报告页。
- 已有结构化数据（CSV/Excel/JSON/表格），需要 KPI、图表、数据表与结论一体的可交付 HTML。
- 报告需要可打印、可转发，离线双击能打开。

不适用：需要定时刷新、接实时数据源的监控看板；只要一个概览看板页；纯图表组件选型与模板库。

## 布局顺序

1. **头部**：报告标题、时间区间、数据来源与口径说明。
2. **KPI 卡网格**：3–5 个最重要指标，每张卡显示数值、同比/环比与微型趋势线。
3. **主图表区**：至少 2 个图表（柱状/折线/环形/散点等），围绕结论选图，不堆图。
4. **数据表格**：原始数据节选，斑马纹、sticky 表头；最高/最低值用色阶或标记点出。
5. **洞察块**：3–5 条基于真实数据的结论，每条对应到具体指标或图表，不用 emoji 堆砌。
6. **方法论折叠区**：口径、假设、缺失值处理方式，用 `<details>` 收起。

## 数据纪律

- **必须使用用户提供的真实数据**，禁止 lorem ipsum、占位数字与虚构指标。
- 输入是 CSV/Excel/JSON 时先解析，再选 KPI 与图表；数据不足如实说明，不补缺失值。
- 同比/环比、占比等派生数字要能从原始数据算出来；口径写进方法论区。
- 洞察只能陈述数据支持的结论；数据看不出的因果，标为待验证，不写成定论。

## 图表实现约束

- **容器必须有固定高度**：外层 `position:relative; height:280px`，迷你趋势线 40–60px。图表库开 `responsive: true, maintainAspectRatio: false` 时，父容器缺高度会导致布局卡死。
- 零依赖约束下图表用内联 SVG 或 CSS 绘制；不引外部图表库与 CDN。
- 表格行不跨页断裂；长表表头在打印时重复。

## 交付前核对（第三方技能踩过的坑）

- **核对声称的依赖是否随包提供**：文档写「支持流程图/某图表库」，先确认对应文件真的在包里。缺库时流程图不能把一段代码原样躺在页面上；降级为内联 SVG、纯表格或文字步骤，并在交付说明里标明该部分不可用。
- **不把未安装的能力写进承诺**：技能安装报「不在可安装目录」时，先核对目标目录是否在安装器清单内，不要假设环境已装好。
- 导出 PDF/截图时，本地图片必须用相对路径并经本地 HTTP 服务加载；绝对文件路径在无头浏览器里读不到。

## 与相近技能的分界

| 手上的活 | 用 | 别走这份 |
|---|---|---|
| 一期数据出可交付报告 | 本技能 | `dashboard`（单页概览看板） |
| 团队实时动态与活动流 | `live-dashboard` | 本技能 |
| 选图表模板与配色组件 | `lieflat-charts` | 本技能 |
| 网页转 PDF 交付 | `html-to-pdf` | 本技能 |
