# 外部资源与整合技能 · 按意图加载说明

这份文档回答：使用者要找灵感、找现成组件，或想调用已经整合进来的外部技能时，AI 该怎么选、怎么读、读多少。

它和 `docs/intent-routing.md` 的关系是：那份负责判断该用哪个技能产出界面，这份负责判断要不要读外部资源索引、要不要调用整合技能。两者都由仓库根 `SKILL.md` 调度。

## 一条硬规则

默认不加载 `references/resources/` 里的任何索引文件。

只有意图明确落在下面两类时才读；命中后一次最多读一份分类文件。使用者要的是产物（页面、图标、配色、代码），就直接走 `skills/` 下的技能，别先翻资源清单。

整合技能本身是 `skills/` 下的正式技能，由 `docs/intent-routing.md` 的常规流程匹配，不需要额外加载规则。仓库共 78 个技能，一次只命中 1 个主技能加最多 2 个辅助技能。

## 两部分内容

| 部分 | 路径 | 内容 | 状态 |
|---|---|---|---|
| 资源索引 | `references/resources/` | 共具 9 类资源索引，37 条仓库链接 + 103 条站点 | 网址清单，按需查，不是收录的源码 |
| 整合技能 | `skills/foundations/` | 5 个由外部技能内容改编而来的正式技能 | 已纳入 78 个技能，可安装、可路由、可校验 |

五个整合技能：

| 技能 | 管什么 |
|---|---|
| `design-vocabulary` | 设计词汇与逐维整改指令 |
| `art-direction` | 艺术方向与参考图拆解 |
| `a11y-rules` | 可访问性细则与检查清单 |
| `motion-craft` | 动效配方、性能与组件细节 |
| `motion-prompts` | 动效提示词的写法与格式 |

它们使用本库统一的命名与 `SKILL.md` 格式，规则文本放在各自的 `references/` 下，由该技能的 `SKILL.md` 决定读哪几份。归属与许可统一登记在根目录 `THIRD-PARTY.md`。

## 意图分流

| 使用者大概会这么说 | 走哪里 | 具体读什么 |
|---|---|---|
| 有没有现成的组件库、UI Kit | 资源索引 | `01-components.md` |
| 找点设计灵感、参考截图、配色站 | 资源索引 | `02-inspiration.md` |
| 要动效参考、背景、插画素材 | 资源索引 | `03-motion.md` |
| 有没有前端审美 Skill、UI 提示词库 | 资源索引 | `04-ai-tools.md` |
| 要落地页模板、现成 section | 资源索引 | `05-templates.md` |
| 参考开源 SaaS 产品界面 | 资源索引 | `06-growth.md` 或 `09-open-source.md`，二选一 |
| 界面质感不行，想按具体维度改 | 整合技能 | `design-vocabulary` |
| 要先定艺术方向、拆解参考图 | 整合技能 | `art-direction` |
| 逐条核对可访问性、表单、触控热区 | 整合技能 | `a11y-rules` |
| 做动效、动画性能、苹果风格界面 | 整合技能 | `motion-craft` |
| 把动效需求写成可复用提示词 | 整合技能 | `motion-prompts` |
| 给我做个落地页 | 常规技能 | `saas-landing` |
| 帮我做一套图标 | 常规技能 | `icon-system` |

判断顺序：先看是不是要产物。是就走技能，不读资源索引。只有出现找、有没有、参考、灵感、别人怎么做这类信号，才打开 `references/resources/`。

## 加载步骤

1. 资源索引：先读 `references/resources/INDEX.md`，再只读命中的那一份 `0X-*.md`。
2. 整合技能：按常规流程读该技能的 `SKILL.md`，再按其中约定取 `references/` 下 1 到 3 份。
3. 从里面挑与需求直接相关的条目或规则，给结论。不要整份清单复述，不要罗列无关链接。

## 兜底

| 情况 | 怎么做 |
|---|---|
| 分不清该查资源还是该用技能 | 问自己：要的是网址还是产出。要网址查资源索引，要产出走技能 |
| 资源索引里跨两类 | 一次最多读两份 `0X-*.md`，优先读更具体的那一类 |
| 多个整合技能都像 | 按 `docs/intent-routing.md` 的裁决规则选一个主技能，最多加两个辅助 |
| 都没命中 | 不读资源索引，按 `docs/intent-routing.md` 的六步兜底路径走 |
| 使用者只是问有哪些资源 | 只读 `references/resources/INDEX.md` 给分类概览，不展开 140 条链接 |
| 使用者要一份完整清单 | 说明清单在 `references/resources/SOURCE.md`，按需取用，不要把全文贴进回复 |

## 反例

| 不要这样 | 应该这样 |
|---|---|
| 一进仓库就把资源索引 9 份全读一遍 | 先判断意图，命中才读一份 |
| 一进仓库就把 78 个 SKILL.md 全读一遍 | 只读命中的 1 到 3 个技能 |
| 做落地页之前先翻组件站 | 直接走 `saas-landing`，产出后再按需找素材 |
| 把 140 条链接全列给用户 | 只给与需求相关的三五条 |
| 把整合技能当成参考资料而不是可执行技能 | 它有标准 `SKILL.md`，按常规流程加载并产出 |

## 口径

资源索引是外部网址，不是本库收录的源码；链接按收集时原文保留，未核验时效，也未统一改写成 HTTPS。带两个地址的是同一资源的主链接与第二地址。

五个整合技能由外部技能内容改编，使用本库统一命名与格式，规则文本已去掉原作者署名。MIT 与 Apache-2.0 要求的版权声明保留在 `references/licenses/` 下五份许可文件中，并在 `THIRD-PARTY.md` 集中登记，不得删除。

## 维护

- 改链接只改 `references/resources/SOURCE.md`，然后跑 `python tools/build_resource_index.py`。9 个分类文件与 `INDEX.md` 都是生成物，不要手改。
- 新增整合技能时，按 `docs/intent-routing.md` 的维护约定同步根 `SKILL.md`、`ROUTER.md`、`docs/skill-map.md` 与本文件，再跑 `tools/build_index.py` 重算清单。
- 新增或改动加载规则时，根 `SKILL.md`、`docs/intent-routing.md` 与本文件三处口径保持一致。
