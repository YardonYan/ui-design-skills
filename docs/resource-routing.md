# 资源层与智慧层 · 按意图加载说明

这份文档回答：使用者要找灵感、找现成组件、找 UI 技能，或者想借外部设计经验时，AI 该读哪一份文件、不该读哪些。

它和 `docs/intent-routing.md` 的关系是：那份负责判断`该用哪个技能产出界面`，这份负责判断`要不要读外部参考资料`。两者都由仓库根 `SKILL.md` 调度。

## 一条硬规则

默认不加载任何资源索引或外部智慧文件。

只有意图明确落在下面两类时才读；命中后一次最多读一份资源分类文件，或最多三份外部智慧文件。使用者要的是产物（页面、图标、配色、代码），就直接走 `skills/` 下的技能，别先翻资源清单。

这条规则是为了控制上下文体积。清单有 140 条链接、外部智慧有 169 份 Markdown，全灌进上下文既慢又会让回答失焦。

## 两层结构

| 层 | 路径 | 内容 | 总览 |
|---|---|---|---|
| 资源层 | `references/resources/` | 9 类外部链接索引，37 条 GitHub + 103 条站点 | `INDEX.md` |
| 智慧层 | `references/wisdom/` | 5 个上游技能仓库的文本内容，169 份 Markdown | `INDEX.md` |

资源层是网址，用来`去哪找`；智慧层是别人写好的规则与提示词，用来`怎么做更好`。两者都不替代 `skills/` 下的 67 个技能。

## 意图分流

| 使用者大概会这么说 | 读哪一层 | 具体读什么 |
|---|---|---|
| 有没有现成的组件库、UI Kit | 资源层 | `01-components.md` |
| 找点设计灵感、参考截图、配色站 | 资源层 | `02-inspiration.md` |
| 要动效参考、背景、插画素材 | 资源层 | `03-motion.md` |
| 有没有前端审美 Skill、UI 提示词库 | 资源层 | `04-ai-tools.md` |
| 要落地页模板、现成 section | 资源层 | `05-templates.md` |
| 参考开源 SaaS 产品界面 | 资源层 | `06-growth.md` 或 `09-open-source.md`，二选一 |
| 界面质感不行，想按具体维度改 | 智慧层 | `impeccable/SKILL.md` 与命中的 `reference/*.md` |
| 要先定艺术方向、拆解参考图 | 智慧层 | `taste-skill/SKILL.md` 与命中的 `references/*.md` |
| 逐条核对可访问性、表单、触控热区 | 智慧层 | `jakubkrehel/better-accessibility/` 下命中的文件 |
| 做动效、动画性能、苹果风格界面 | 智慧层 | `emilkowalski/` 下命中的 `SKILL.md` 或 `RECIPES.md` |
| 把动效需求写成可复用提示词 | 智慧层 | `motion-prompt/FORMAT.md` 与 `prompts/en/` 下命中的文件 |
| 给我做个落地页 | 都不读 | 直接走 `skills/web/saas-landing/` |
| 帮我做一套图标 | 都不读 | 直接走 `skills/components/icon-system/` |

判断顺序：先看是不是`要产物`。是就走技能，不读这两层。只有出现`找、有没有、参考、灵感、别人怎么做、提升质感`这类信号，才进入资源层或智慧层。

## 加载步骤

1. 读对应层的 `INDEX.md`，确认该读哪一份。总览各约 30 行，读完不要复述。
2. 只读命中的那一份分类文件，或进入命中的一个来源目录先读它的 `SOURCE.md`。
3. 从里面挑与需求直接相关的条目或规则，给结论。不要整份清单复述，不要罗列无关链接。

## 兜底

| 情况 | 怎么做 |
|---|---|
| 分不清该进资源层还是智慧层 | 问自己：要的是`网址`还是`规则`。要网址进资源层，要做法进智慧层 |
| 资源层里跨两类 | 一次最多读两份 `0X-*.md`，优先读更具体的那一类 |
| 智慧层里多个来源都像 | 只读一个来源，优先选与产物最接近的；不够再换 |
| 都没命中 | 不读这两层，按 `docs/intent-routing.md` 的兜底路径走技能 |
| 使用者只是问`有哪些资源` | 只读资源层 `INDEX.md`，给分类概览，不展开 140 条链接 |
| 使用者要一份完整清单 | 说明清单在 `references/resources/SOURCE.md`，按需取用，不要把全文贴进回复 |

## 反例

| 不要这样 | 应该这样 |
|---|---|
| 一进仓库就把两层 INDEX 和 9 个分类文件全读一遍 | 先判断意图，命中才读一份 |
| 做落地页之前先翻 01 类组件站 | 直接走 `saas-landing`，产出后再按需找素材 |
| 把 140 条链接全列给用户 | 只给与需求相关的三五条 |
| 把智慧层当成可安装技能 | 它是参考语料，产出仍由 `skills/` 下的技能负责 |
| 改写上游 Markdown 让它更顺 | 原文收录，加工写成本库自己的文件 |

## 口径

资源层是外部网址索引，不是本库收录的源码，内容、可用性与许可均以原站点为准；链接按收集时原文保留，未核验时效，也未统一改写成 HTTPS。带两个地址的是同一资源的主链接与第二地址。

智慧层按上游原文收录，未改写，是 2026-11-15 的快照，每个来源目录都带 LICENSE 与 `SOURCE.md`，写明上游、许可、收录范围与用途。许可分别见各目录，MIT 与 Apache-2.0 的版权声明不得删除。

## 维护

- 改链接只改 `references/resources/SOURCE.md`，然后跑 `python tools/build_resource_index.py`。9 个分类文件与两个 INDEX 都是生成物，不要手改。
- 智慧层新增来源时，把文本放进新目录并补一份 `SOURCE.md`，再跑同一个脚本重算 `wisdom/INDEX.md`。
- 新增或改动加载规则时，同步更新根 `SKILL.md`、`docs/intent-routing.md` 与本文件，三处口径保持一致。
